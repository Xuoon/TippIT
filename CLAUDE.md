# TippIT

Tray-App für Windows und macOS (nur Apple Silicon), Rust + Tauri v2 + Svelte 5/SvelteKit static: STRG+Y (macOS: ⌘Y) tippt die Zwischenablage als Tastatureingaben, STRG+SHIFT+Y (⌘⇧Y) öffnet die verschlüsselte Historie; optionaler E2E-verschlüsselter Sync über Convex (`convex/`).

## Commands

- Laufendes TippIT vor `bun dev` beenden; der Befehl startet Tauri/Vite + Convex im Turbo-TUI. `bun run tauri build` erzeugt NSIS + Updater-Signatur (Windows, `src-tauri/target/release/bundle/nsis/`) bzw. App/DMG + Updater-Tarball (macOS, `…/bundle/macos/` + `…/bundle/dmg/`). Signiert wird mit `TAURI_SIGNING_PRIVATE_KEY` aus `.env.local` — das lädt nur der Launcher `scripts/tauri.js` (`bun run tauri …`); ein direkter Tauri-Aufruf scheitert beim Signieren.
- `cargo test` + `cargo check` in `src-tauri/`; Frontend-Typcheck: `bun run typecheck`; Lint/Format: `bun run fix` (prüfen: `bun run check`; Ultracite-CLI auf Biome mit vendortem Core-/Svelte-Preset in `.ultracite/`).
- Frischer Clone: erst `bun install && bun run build`, sonst scheitern kompilierende cargo-Befehle wie `cargo check/test/clippy` (`generate_context!` verlangt `../build`)
- Release: Version in `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` und `package.json` bumpen + CHANGELOG-Abschnitt → Push auf `main` released automatisch (`.github/workflows/release.yml`, baut Windows + macOS und published EIN `latest.json` mit beiden Plattform-Keys)

## Invarianten

- **Direkte native OS-APIs nur in `src-tauri/src/platform/`** (`win.rs`/`mac.rs`, identische API); Fachmodule bleiben plattformneutral. Ziel-/Dependency-`cfg` in Manifesten bzw. Modul-Wiring ist zulässig. Im Frontend ist `src/lib/platform.ts` die EINZIGE Plattformweiche (Modifier, Hotkey-Labels — Symbol-Parität mit `platform::{win,mac}.rs::display_hotkey`). Plattform-Fallstricke: `.claude/rules/windows.md` und `.claude/rules/macos.md`.
- **Krypto-Crates bleiben auf der 0.10-Serie** (`aes-gcm 0.10`, `hkdf 0.12`, `sha2 0.10`, `src-tauri/Cargo.toml`) — die 0.11-Serie hat eine inkompatible API (hybrid-array statt GenericArray).
- **Ciphertext-Format nie ändern:** `nonce(12) ‖ AES-256-GCM`, AAD = `version ‖ kind ‖ uuid` (`storage/crypto.rs`). Derselbe Blob dient lokal at-rest UND als Sync-Payload. Schlüsselrotation hält `state::rotation_lock` über DB-Umschlüsselung + Key-Swap; jeder Pfad mit gemeinsamem DB-/Key-Snapshot muss dieselbe Barriere halten.
- **Eigene Clipboard-Writes:** NACH jedem erfolgreichen `set_text`/`set_image` `clipboard::read::mark_own_write(&state)` aufrufen (`history.rs`, `sync/pairing.rs`) — der Monitor überspringt genau diese Sequenznummer; ein Zähler-Ansatz leckt bei fehlgeschlagenen Writes.
- **Vor der Injektion auf physisches Loslassen aller Modifier warten** (`typing.rs::wait_modifiers_released`) — sonst feuert der getippte Text als Shortcuts im Zielfenster. Davor prüft `type_text` die Eingabe-Berechtigung (`platform::ensure_input_permission`, macOS-AX-Guard) und bricht ohne Freigabe mit Fehlerton ab. Abbruch ist fest ESC und wird NUR für die Dauer eines Vorgangs global registriert (`typing::EscCancelGuard`) — nie dauerhaft, sonst schluckt TippIT systemweit jede ESC-Taste.
- **Historie-Fenster nie zerstören, nur verstecken** (`windows_util.rs`): CloseRequested → `prevent_close()` + hide (WebView-Neuaufbau ~300–800 ms). Beim Öffnen wird ZUERST das Vordergrund-Ziel als Tipp-Ziel gemerkt (`prev_target`), DANN das Fenster aktiviert; Sichtbarkeit immer über `platform::window_visible`/`hide_window`, nie Tauris `is_visible` direkt. Kein Hide-on-blur — Schließen nur via X/Esc/Hotkey.
- **`tauri-plugin-single-instance` muss das erste Plugin bleiben** und schwere Initialisierung gehört in `setup()` (`lib.rs`), damit Zweitstarts sofort abbrechen.
- **Auslieferungs-Defaults** (z. B. Convex-URL) stehen in `src-tauri/defaults.json` und werden per `include_str!` in die EXE eingebettet (`storage/settings.rs::shipped_defaults`); das Frontend liest sie über den Command `default_settings` — Defaults nie im Frontend duplizieren. Vor Release-Builds pflegen.
- **Sync-Limits synchron halten:** `MAX_INLINE_CIPHER` (900 KB) und das Push-Bytebudget (8 MiB) existieren in `convex/sync.ts` und `src-tauri/src/sync/mod.rs`; beide zählen `cipher + thumb`. `PULL_PAGE` bleibt so klein, dass Worst-Case-Einträge unter dem Convex-Ergebnislimit bleiben.
- **LWW-Konflikte** entscheiden über das Tupel `(lamport, deviceId)` (`sync/protocol.rs::is_newer`); der **Pull-Cursor ist die serverseitige `seq`** (`convex/sync.ts`), NIE der Client-Lamport (Gleichstände/verspätete Pushes würden Einträge dauerhaft verlieren). Convex-Funktionen autorisieren über `sha256(authKey)`-Vergleich — neue Funktionen immer zuerst `requireGroup()` aufrufen lassen (`convex/lib.ts`).
- **Settings-Sync nutzt eine versionierte `SyncableSettings`-Allowlist** (`sync/mod.rs`): Hotkeys, Server-URL, Zeitplan und Systemrichtlinien bleiben geräte-lokal und dürfen nie im Payload landen. Neue Settings immer bewusst als synchronisiert oder lokal klassifizieren; Hotkey-Defaults sind plattformspezifisch (ctrl vs. cmd).
- **Source-App (Quellanwendung) ist geräte-lokal** — `source_app_id`/`source_app_name` in SQLite + Index, **nicht** in `SyncEntry`/Convex; normale Remote-Updates bewahren lokale Source-Spalten, Tombstones leeren sie. Capture-Duplikate: fremde `Some(app)` → `TouchSource::Set`, TippIT selbst → `Clear`, transient `None` → `Keep`; `copy_entry` nutzt immer `Keep`. Icons unter `~/.labi/tippit/app-icons/` (hash-safe, lazy Command `source_app_icon`).
- **Historie-/Update-Fenster transparent** (`windows_util`: `.transparent(true)` + CSS `--r-2xl` + `platform::round_window_corners`) — macOS braucht Tauri-Feature `macos-private-api` + `app.macOSPrivateApi` in `src-tauri/tauri.conf.json`. Settings bleibt dekoriert/opak.
- **TOTP/Links** sind clientseitige Text-Verfeinerungen in `entry-kinds.ts` (keine Backend-kinds); der **TOTP-Code wird clientseitig live erzeugt** (`totp.ts`, Web Crypto) — Kopieren/Tippen eines TOTP-Eintrags nutzen den Code, NIE das Secret. **Kontextuelle Primäraktion** (`primaryAction`, ⇧+Enter / Detail-Button): Links/Dateien via `open_entry` öffnen (nur http(s) + KIND_FILES-Pfade — keine beliebigen Schemes), Bild → OCR, sonst Tippen. `type_text` tippt beliebigen Text über denselben `spawn_type`-Kern (Vordergrund-Verifikation!) wie `type_entry`. Sortierung nutzt `first_created_at`/`copy_count` (Schema v3). OCR: `platform::ocr_png` → `Vec<OcrLine>` (macOS Vision `boundingBox`; Windows Stub).
- **Bilder: Liste nutzt Thumbnail, Detail-Vorschau das Vollbild.** `entry_thumb` (≤256px, in jeder Zeile) vs. `entry_image` (voller cipher, LAZY nur für den ausgewählten Eintrag — Blob kann mehrere MB groß sein). Vorschau nie auf das Thumbnail zurückstutzen (unscharf), Liste nie aufs Vollbild (Speicher). Das OCR-Overlay misst die gerenderte `<img>`-Box (`ResizeObserver`), weil `object-fit`-Skalierung nicht in CSS abbildbar ist.
- Datenverzeichnis ist fest `~/.labi/tippit/` (Windows: `%USERPROFILE%`, `storage/paths.rs`), nicht APPDATA/Application Support; kein Legacy-Fallback auf `.labit`.
